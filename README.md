# AI Studio Manager 移行スクリプト v1.0 — 実行手順

設計書: AI_Studio_Manager_新スキーマ設計書_v1.0.md
所要時間: 全体で30分程度(スクリプトの実行自体は各数十秒)

## このスクリプトがやること

1. 新環境スプレッドシート(7シート構成)を自動作成する
2. Master_Logのスナップショットを読み、新スキーマへ変換して書き込む
3. 結果と要確認事項を「移行レポート」シートにまとめる

**移行元(スナップショット)には一切書き込みません。読むだけです。**

## 事前準備

1. 大本のMaster_Logを複製し、名前を `Master_Log_snapshot_20260801` のように日付入りにする
2. そのスナップショットのスプレッドシートIDを控える
   (URLの `/d/` と `/edit` の間の長い文字列)

## 手順

### Step 1: スクリプトプロジェクトを作る

1. https://script.google.com で「新しいプロジェクト」を作成
2. 名前を「ASM移行スクリプト」にする
3. このZIPの4つの `.gs` ファイルの中身を、それぞれ同名のファイルとして貼り付ける
   (エディタ左の「+」→「スクリプト」でファイルを追加)

### Step 2: 新環境を作る

1. `00_config.gs` の `SNAPSHOT_SPREADSHEET_ID` にスナップショットのIDを貼る
2. エディタ上部の関数選択で `setupNewEnvironment` を選び「実行」
3. 初回は権限の許可を求められるので許可する
4. 「実行ログ」に表示されたIDを `00_config.gs` の `TARGET_SPREADSHEET_ID` に貼る

### Step 3: dryRun(お試し実行)

1. 関数選択で `dryRun` を選び「実行」
2. 新環境スプレッドシートを開き、「移行レポート」シートを確認する
   - 顧客数・撮影数・注文数がだいたい合っているか
   - 「要確認」の件数と内容が納得できるか
3. **この段階ではどこにも本データは書き込まれていません。**
   何度実行しても安全です。

### Step 4: 本実行

1. レポートに問題がなければ、関数選択で `migrate` を選び「実行」
2. 新環境の各シートにデータが入っていることを確認する
3. 「移行レポート」の要確認一覧は、Web画面が完成したらそこから順次確定していく
   (今すぐ全部片付ける必要はありません)

## やり直したいとき

- 新環境のデータを消して流し直す:
  `00_config.gs` の `CLEAR_BEFORE_MIGRATE` を `true` にして `migrate` を再実行。
  終わったら `false` に戻す。
- 本番切替のときも同じ手順で、最新のスナップショットから流し直せます。

## 設定できる値(00_config.gs)

| 設定 | 意味 | 初期値 |
|---|---|---|
| COMPLETION_DAYS | 撮影日からこの日数を超えた案件を「完了(移行時推定)」にする | 90 |
| ADULT_GENRE_KEYWORDS | 成人記念として扱うジャンルの文字 | 成人/振袖/二十歳/はたち |
| CLEAR_BEFORE_MIGRATE | 再実行時に既存データを消すか | false |

## 困ったとき

- エラー「移行先にCustomersシートがありません」
  → TARGET_SPREADSHEET_ID の貼り間違い。Step 2-4 を確認。
- エラー「移行先に既存データがあります」
  → 二重実行の防止機能です。流し直すなら CLEAR_BEFORE_MIGRATE を true に。
- 日付やジャンルの不備は移行を止めず「要確認」として取り込まれます。
  レポートの一覧から後で直せます。
